## §1. ladyland とは

**8〜12 の自分の楽器を住まわせ、持ち替えながら完全即興を演奏するための macOS アプリ。**
楽器たち（electric ladies）の住む場所の名を、楽器たちを束ねるアプリが襲名した。

試金石ライブ（2026-08-08 大阪）の価値基準は doc 05 §1 を継承する:
1. **確実に動く** — 本番で落ちない・音が出ないが起きない
2. **後から何が起きたか分かる**

加えて本アプリの設計原則: **物理楽器なみシンプル** — 楽器を持ったら触れるところは自明で少ない。複雑なマッピング体系・モード・バンクを作らない。

## §2. 確定要件（2026-07-30 ヒアリング）

- **完全即興**。曲・セクションの概念なし。ファイル再生なし・完全手弾き。映像なし（field は 8/8 後の本丸、`mem_1CdXiVM8pgKHpQRD9JbDGG`）
- **8 スロット**の AU インストゥルメントを常駐（12 へは将来 LPD8 プログラム切替で拡張可）
  - 根拠 = mako の経験則: **スタジオセッションは約 40 分で 7〜8 音色**を使う。8 スロット = 実測にぴったり
- **音色は ladyland 内で作る**: 音を出しながらプリセットを探し、AU 画面でいじり、保存。**再起動しても自分の楽器がそのまま並んでいる**
- 音色の分担: **作る場所 = プラグイン自身の画面**（Serum / Gadget のブラウザ）、**残す仕組み = ホスト側 state 保存**（`auAudioUnit.fullState`）
- 音量バランス・全体の最終調整 = **L6max（物理ミキサー、MIDI 連携なし）**

## §3. 機材と入力の役割（演奏面と制御面の分離）

| 面 | 機材 | 役割 |
|---|---|---|
| **演奏面** | Keystage 鍵盤 | 選択中の楽器を弾く（ポリ AT 対応） |
| **演奏面** | Keystage ノブ 8 | 選択中の楽器の**顔つまみ**（楽器ごと 2〜4 個で十分） |
| **演奏面** | LPD8 パッド 8 | **第 2 の声部**。LPD8 スロット（任意の AU — ドラムに限らずシンセも載る）を叩く — Keystage の持ち替えから**独立**。指ドラムにも**セカンドキーボード**（ベースのルート / パッド和音）にもなる（2026-07-30 実機で確認、mako「シンセも割り当てて使いかも。セカンドキーボードとしてもいける」） |
| **制御面** | GUI（一級市民） | ミキサー + 状態表示（スロット一覧・選択中・レベル）+ クリックで選択 |
| **制御面** | PC 数字キー 1-8 | スロットのダイレクト選択 |
| **制御面** | PC 方向キー ←→ | スロットの順送り / 戻し（即興中の「隣へ流れる」持ち替え） |
| **制御面** | PC 方向キー ↑↓ | **選択中スロットのマスター音量の増減**（十字キーだけで「持ち替えて整える」が完結） |
| **制御面（追加レイヤー）** | ROTO-CONTROL | **GUI の物理ミラー**（LCD にパラメータ名、モーターノブで状態が手に還る）。間に合えば乗せる。**無くても完全に成立**（fail-open） |
| 出口 | L6max | 物理ミキサー。cortex 時代の MIDI 双方向はスコープ外 |
| 不参加 | FGDP-50 | 今回は使わない |

同時発音の前提: 選択中の楽器 1 + ドラムスロット 1 +（切替時のリリース 1）= **常時 2〜3**。AVAudioEngine + Gadget の軽さなら M5 / 24GB で余裕。

## §4. アーキテクチャ

### 技術基盤 — AU ホスティングは Swift のホームグラウンド

| 課題 | API |
|---|---|
| AU ロード・音声グラフ | `AVAudioEngine` + `AVAudioUnitMIDIInstrument`（`AVAudioUnit.instantiate`） |
| 音色の保存・復元 | `auAudioUnit.fullState`（プロパティ一発。DAW のプロジェクト保存と同じ層） |
| AU 画面 | `auAudioUnit.requestViewController` — ネイティブなので main thread 問題が存在しない |
| MIDI 入力 | CoreMIDI（`MIDIInputPortCreateWithProtocol`） |
| 出力デバイス固定 | CoreAudio — 「ZOOM L6max」を名前で選び `AVAudioEngine` の出力に設定 |
| UI | SwiftUI |

rack（Rust）はこれら API の FFI ラッパーだった。ladyland は本物を直接触る。

### 音声グラフ

```
slot[0..7]: AVAudioUnitMIDIInstrument ─┐
drumSlot:   AVAudioUnitMIDIInstrument ─┼→ mainMixer → output(= L6max)
                                       ┘
```

- 全スロット attach + connect したまま常駐（鳴っていないノードはほぼ無負荷）
- **MIDI ルーティングだけを切り替える**: Keystage → 選択中スロット / LPD8 → ドラムスロット
- cortex の「process は選択中 + リリース中のみ」に相当する自前スケジューリングは**不要**（エンジンが面倒を見る）。切替作法（後述）だけ持ち込む

### スロットモデル

```
Slot { index, component(AU識別), fullState(blob), displayName, gain }
Rack { slots[8], drumSlot, selected: Int }
```

- 選択切替: 旧スロットに **All Notes Off (CC123) + サスティンオフ (CC64=0) を全 16ch** へ送り、リリースは自然に鳴り終わらせる（ノードは繋ぎっぱなしなので追加実装不要 — cortex 比で単純化）
- 保存: `Rack` 全体（構成 + 各 `fullState`）を Application Support 配下へ。終了時 + 明示保存。起動時に復元

## §5. cortex から持ち越す設計資産（コードは置いていく、学びは持っていく）

1. **deny list**: `Splice` は名前部分一致で全ロード経路から遮断（AU Instrument 自称のサンプルブラウザ。null mutex SIGSEGV、2026-07-30 実機クラッシュ）
2. **KORG Gadget**: 34 ガジェット = 個別 AU。**マシンごとに KORG 認証必須** — 未認証はロード成功なのに無音（RMS=0）で失敗が見えない
3. **切替作法**: All Notes Off + サスティンオフ全 16ch（Memphis 実測でリリース減衰 4.4e-5 まで確認済み）
4. **Keystage**: MIDI Clock (F8) 常時送信 → 入力段で Realtime を弾く / ノブは終点ありポット → 顔つまみ割当にはピックアップ動作
5. **クラッシュ解析**: `~/Library/Logs/DiagnosticReports/*.ips` を最初に見る

## §8. 設定ウィンドウ + LPD8 SysEx 統合（2026-07-31 起工、plan: ok-plan-memoized-stonebraker）

8/8 前に全部 nightly へ入れる（mako 裁定）。非モーダル補助ウィンドウ「開いて確認して閉じる」— 演奏・楽器エディットを隠さない。

- **設定ウィンドウ**（`SettingsWindow.swift` / `SettingsView.swift`）: PluginEditorWindows と同じ NSWindow 直接管理。gear ボタン / Cmd+, で開く。タブ = オーディオ出力 / LPD8（/ キー・スケール予定）
- **キーモニタのガード**: 設定ウィンドウが key の間は 1-8/矢印を飲まない（TextField を壊さない）。ミキサーが key の時のライブ挙動は不変
- **副作用（既知・許容）**: 設定ウィンドウが開いている間はミキサーを閉じてもアプリが終了しない（applicationShouldTerminateAfterLastWindowClosed の仕様。プラグイン画面と同じ）
- **出力デバイス切替**（予定）: ランタイム切替 resolve→stop→set→start、UID 永続化（RackSnapshot.outputDeviceUID）、L6max 既定 pin は不変
- **LPD8 mk2 SysEx**: Lpd8Kit（GET 0x03 / SET 0x01 / LED 0x06、プログラム構造は実機ゴールデンで byte 単位確定 — spec/04 参照）。**LED 実測 = サービス 107ms/frame ≈ 9-10fps 上限**（RigBench lpd8-led-rate、Creo mem_1CdZe314eTYVofGrhZN6xy）
- **LedBus（実装済み）**: completion-gated（in-flight 1、完了コールバック = 次送信の合図）+ shadow 差分（量子化後ワイヤ値比較 — アイドル時トラフィック 0）+ 合成（flash > メーター輝度 > 基本色）+ watchdog 1s（抜線自己回復）+ キルスイッチ（設定 LPD8 タブ、永続化）。終了時は全消灯（0x06 上書きは挿し直しまで実機に残るため）
- **KeyScale（実装済み）**: ルート 0-11 + スケール 7 種（メジャー/マイナー/ドリアン/ミクソ/ペンタ×2/クロマチック）。パッド → ノート対応は実機プログラム 1 の観測値（44-47/40-43）を既定とし、エディタの GET で実機に追従。LED 基本色 = ルート橙 / 内 青 / 外 消灯。設定タブ「キー・スケール」、rack.json に永続化
- **プログラムエディタ（実装済み）**: 読み込み = GET 0x03（実機バイトが正）→ パッド 4×2 グリッド（物理配置準拠、note/CC/PC/ch + on/off 色）+ ノブ 8 行 + グローバル → 書き込み = 確認ダイアログ → SET 0x01 → **GET-back 照合**。SysEx 受信は drums ポートに SysEx7Assembler を同居（MT2 ノート経路は不変）。送受信中は LedBus suspend。**本番セット中は使わない**（手順書に明記）
- **プリセット（Profile 構想の層 1、実装済み）**: GET した実機状態に名前を付けて `~/Library/Application Support/ladyland/profiles/lpd8/*.json` へ保存・適用（適用は working copy まで — 実機反映は明示の書き込み）。「実機だけが設定の保存場所」という怖さを消す。層 2（ステージセット = 出力 + キー + LED の束）は 8/8 後の候補
- **タイル並び替え（実装済み）**: 番号バッジ = ドラッグハンドル（grip + 番号。クリック選択・サムネタップ・メニューと構造的に不干渉 — ライブ中の誤発ゼロ）。ドラッグ開始で Lane 上に **Layout Grid Frame**（8 セルの枠ガイド）が浮かび、ホバー先を brand primary で着地予告、リリースで**スワップ**確定（他タイルは不動 — 数字キー 1-8 / LED パッドの対応を保つ）。実体はスロット中身（AU・名前・gain・つまみ割当）の交換で位置＝同一性（index）は不動、選択は楽器に追従 → keyboard target の AU が変わらず **All Notes Off 不要で音が切れない**。エディタウィンドウの index キーも同時交換（`PluginEditorWindows.swap`）。永続化・サムネは自動追従。ドラム枠は対象外。着地はセル/タイル分離 + settle アニメ完了時のモデル交換で無縫（`TileDrag.swift` / `InstrumentRack.swapSlots`）
- **Debug ウィンドウ（実装済み）**: ladybug ボタン / Cmd+D の非モーダル補助ウィンドウ。stderr をパイプで横取りして NSLog を全部アプリ内に映す（元 stderr へ書き戻すのでターミナル出力も生存。⚠️ Pipe は**プロパティ保持必須** — ローカル変数のままだと ARC が read 端を閉じ、以降の NSLog が SIGPIPE で exit 141 の即死）。フィルタ / 追尾 / クリア、リングバッファ 500 行。**MIDI ルーティングトレース**: MIDIRouter が判断の瞬間（横取り/ナビ/未割当 ch16/keyboard/drums）に `MidiRoute` 値型を RT で発行 → main で名前解決・整形（`MidiTraceFormat` 純関数）。連続ストリーム（ノブ CC・AT・PB・ナビ）は collapse key で最後の行を置き換え ×N を積む（ノート類は 1 発ずつ残す）。RT スレッドの NSLog は全廃（ブロック回避、トレースに一本化）
- **Rack 常時保存（実装済み、mako 裁定「なるべく常に保存くらいの勢い」）**: quit 時のみ保存を廃し、変更の 1 秒静止後に自動保存（デバウンス — ↑↓ 連打・ノブ回し中の I/O 連発を防ぐ）+ 変化がなければ書かない dedup（前回書いたバイト列と比較。JSONEncoder の決定性はテストで固定）。**トリガー全 14 経路**: ①選択 ②順送り ③戻し ④ロード/差し替え ⑤タイル並び替え ⑥音量 ⑦顔つまみ割当 ⑧出力切替 ⑨LED キルスイッチ ⑩キー/スケール ⑪顔つまみ操作（= fullState 変化）⑫プラグイン画面を閉じた節目 ⑬30 秒定期保険（プラグイン UI 内エディットはホストに通知が来ない — この網で拾う）⑭willTerminate（既存の最終保存）。**復元完了までは自動保存を封印**（restore 途中の中途半端なラックを書いて構成を壊さない）。背景: TERM 落ちでタイル配置が失われた実例（2026-08-01。unbundled バイナリは AppleScript quit も効かない）
- **⚠️ AUParameter.string(fromValue:) を呼んではいけない（実機クラッシュ 2026-08-02）**: 割当パネルに現在値を出すため「整形は AU 自身に任せる」つもりで `param.string(fromValue: nil)` を使ったところ、**KORG のプラグイン内で null 参照して SIGSEGV**。AUv2 ブリッジ経由だと `AudioUnitGetProperty`（`_createParameterTree` 由来）でプラグイン本体に文字列変換を問い合わせに行くのが原因で、プラグイン側の実装に依存する。しかも一覧は数十行を毎描画なぞるので踏む確率が高い（ノブストリップの 8 個より blast radius が大きい）。**値と単位から自前で組む**（`ParameterFormat` — 純関数、テスト済み）。`param.value` / `param.unit` の読み取りは従来どおり安全（顔つまみもノブストリップも通っている経路）
- **Mac アプリ化 + AppIcon（実装済み、mako 裁定 2026-08-02「Mac App として、アイコン付きで起動したい」）**: `scripts/build-app.sh` が release バイナリに Info.plist と AppIcon を着せて `dist/Ladyland.app` を組む（`--install` で /Applications、`--run` で起動）。**Xcode プロジェクトは導入しない** — `swift build` / `swift test` の作法を変えないため。**バンドル化は見た目の話ではない**: unbundled の CLI 起動は **⌘Q も AppleScript quit も効かず `willTerminate` が走らない**（TERM 落ちで状態を失った実例）。バンドルにして初めて**終了時保存が確実に走る** + Dock/⌘Tab にアイコンと名前が出る。ad-hoc 署名（`codesign -s -`）— この Mac で AU をホストするには十分、配布するなら Developer ID が要る。バージョンは git から採る（`CFBundleVersion` = コミット数.短縮ハッシュ）。**AppIcon の意匠 = billboard そのもの**（4×3 のタイル、ひとつだけ brand primary で点灯 = 選択中の楽器）— アプリを開いた絵と Dock のアイコンが同じ語彙になる。生成は `scripts/make-appicon.swift`（CoreGraphics。fleetstage の Three.js + headless Chrome と違い平面意匠なのでブラウザ不要 = 再生成が確実）

- **保存が main を塞ぐ問題の解剖と修理（2026-08-03、実測駆動）**: 実機ログで重い保存が最大 544ms かかっており、`AppState` が `@MainActor` + GRDB の `write` が同期なので **30 秒ごとに UI がその分固まっていた**。修理は 2 段構え。①**SQLite 書き込みを書き込みキューへ預ける**（`RackDatabase.saveAsync`）— 順序は `DatabaseQueue` が構造的に保証するので自前のロックは不要、**終了時（`willTerminate`）だけは同期**で書き切る（プロセスが消えたら預けた書き込みも消える。同期保存は同じキューの末尾に並ぶので、待つだけで先行分も書き切れる = 別途フラッシュ機構が要らない）。②これで直ったと思ったが**計測を疑って測り直したら半分だった**: 時計を `refreshAllStateCaches()` の後で開始していたため main の実コストが計測外に落ちていた。正しく測ると **main 512-590ms が残存**し、主役は SQLite ではなく**全 24 席への `fullState` 問い合わせ**（1 席 ~21ms でほぼ均等。50ms 超えは Fairbanks 65.9 / Chiangmai 51.6 の 2 台のみ = 「重い 1 台を避ける」手は効かない）。AU は main 前提の相手で逃がせない。巡回（数席ずつ聞く）を試したが**最大 153ms 残る上にカーソル状態という複雑さを抱える**ため、**mako 裁定で定期保険そのものを廃止**（2026-08-03）— 30 秒タイマーを削除し、重い保存は**節目だけ**（プラグイン画面を閉じた時 / 終了時 / 書き出し）にした。`StateRefresh` は `.none` / `.all` の 2 値。**定期的に固まらないこと**を取った判断で、失うのは「プラグイン画面を開けっぱなしでクラッシュ」した場合の音色エディットのみ（正常終了なら `willTerminate` が全部書き切る）。⚠️ 副作用として**呼び忘れの網が無くなった** — 状態を変える経路は必ず `scheduleAutosave` / `saveRack` を通すこと。⚠️ 教訓: **非同期化は「総時間」ではなく「main 占有」を測らないと直ったか判定できない**（総時間にはキュー待ちが混ざるので、むしろ増えて見える）。保存ログは `(総 ms, main ms)` の 2 本立てにした
- **音色の保存が全部落ちていた（2026-08-03、実機ログ発見）**: `FOREIGN KEY constraint failed` が 30 秒ごとに永続し、**重い保存（fullState = 音色）が一度も通っていなかった**。軽い保存は別経路なので通っており GUI 上は正常に見えるのが厄介。原因はプロセス内の「もう入れた blob」キャッシュ — トランザクションがロールバックすると SQLite の blob 挿入は消えるのに**メモリ上の Set は消えない**ため、以後 `storeBlob` が「もうある」と誤判定して INSERT を省き、`slot.stateHash` が存在しない blob を指して FK 違反 → またロールバック、と**自己増殖**する。加えて Set の変更は GRDB の書き込みキュー上で起きるため MainActor 側と競合しうるデータ競合でもあった。修理は**キャッシュを消して存在確認を毎回 DB に問う**（主キー参照なのでマイクロ秒、blob 本体は運ばないのでキャッシュの目的だった「21MB を渡さない」は保たれる = 正しさと速さが両立する形が実はあった）。回帰テストは同じファイルを開いた別インスタンスに blob を消させて乖離を再現し、**旧実装で実機と同一の FK 違反が出ることを確認してから**修正版に戻した。⚠️ 教訓: **「キャッシュは DB の状態を映す」という前提はロールバックで静かに破れる**（ロールバックはメモリを巻き戻さない）。DB の write ブロック内でプロセス内状態を変えるコードは原理的にこの穴を持つ
